# HO-SC-8W ↔ INKBIRD APK 2.1.11 — протокольное сопоставление

Дата: 2026-09-05. Исследовательская ветка; новые production-записи не разблокируются без натурного подтверждения.

## Статус идентичности

IIC-800 из APK не объявляется аппаратно идентичным HO-SC-8W. Методы IIC-800 используются только как референс протокольного семейства и принимаются для HO-SC-8W лишь там, где совпадают DP, длина/структура кадра и фактическое поведение нашего контроллера.

## DP45 — подтверждённая штатная матрица APK

APK INKBIRD 2.1.11 формирует 34-байтовый DP45 для 8-зонной модели:

- `00 00` + нулевые банки — запрос/refresh текущего ручного состояния;
- `01 01` — старт выбранных зон в последовательном режиме;
- `02 01` — изменение уже идущего последовательного набора;
- `01 00` — старт всех зон одновременно; с нулевыми банками штатный общий Stop All;
- `02 00` — изменение уже идущего одновременного набора.

Оба банка содержат по 8 unsigned 16-bit big-endian значений.

### Запрос свежего ручного состояния

В `Iic800Presenter.getManualTime` штатное приложение для IIC-800 отправляет:

```text
00 00 + 32 нулевых байта
```

то есть полный 34-байтовый DP45 из нулей. Это **не команда остановки**. После ответа `Iic800Presenter.onDpUpdate()` разбирает DP45 так:

- byte 0 — тип команды/ответа;
- byte 1 — `manualMode`;
- первый банк — `remainTime` по зонам;
- второй банк — `wateredTime` по зонам.

Следствие для NikaS: перед штатной модификацией текущего ручного цикла можно получать фактическое состояние контроллера, а не зависеть от исходного локального плана. На HO-SC-8W сам `00 00` refresh ещё должен быть подтверждён натурным read-back тестом; до этого production-код может использовать свежий DP45, пришедший через `status()`/push, но не должен объявлять zero-query физически доказанным.

### Остановка одной зоны

`Iic800ManualPresenter.stopManual()` не уничтожает оставшийся план. Для зоны, отмеченной к остановке, он пишет `0000` и в первый, и во второй банк, а для остальных зон сохраняет текущие `remainTime` и `wateredTime`, после чего отправляет:

```text
01 <manualMode> <8 × remain> <8 × watered>
```

`Iic800SchedulePresenter.stopManual()` делает аналогичную операцию через `02 01`.

Это отличается от текущего обходного пути NikaS `skip_current_manual`, который хранит локальный `_manual_queue_plan` и повторно отправляет только оставшиеся первоначальные длительности. APK показывает более точный механизм: при модификации активной операции нужно сохранить фактические `remain` и `watered` значения контроллера.

Из этого следует stateless-алгоритм Stop Current для последовательного ручного режима:

1. получить свежие DP45 + DP107;
2. убедиться, что DP107 указывает ровно одну активную зону;
3. взять `manualMode` из byte 1 свежего DP45;
4. скопировать оба live-банка DP45 без пересчёта;
5. обнулить 16-bit `remain` и `watered` только активной зоны;
6. отправить один кадр `01 <manualMode> ...`;
7. подтвердить по DP107, что текущая зона выключилась и следующая ожидаемая зона стала активной либо активных зон больше нет;
8. не выполнять автоматический retry при неопределённом результате.

Такой путь потенциально работает и после перезапуска Home Assistant, поскольку не требует `_manual_queue_plan`. До натурного T2 этот алгоритм остаётся кандидатом, а не production-командой.

### Общий стоп

Штатный `stopAllManual()` для 8 зон отправляет:

```text
01 00 + 64 нулевых HEX-символа
```

то есть 34 байта `01 00` + 32 нулевых байта.

На физическом HO-SC-8W ранее подтверждён рабочий путь `01 01` с нулевыми банками. Поэтому production-код не меняется автоматически: сначала нужен безопасный A/B read-back тест штатного `01 00` Stop All на нашем экземпляре.

## DP38 — точный write-формат APK

`Iic800SchedulePresenter.setScheduleTime()` формирует ровно 40 HEX-символов:

```text
[zone mask:2]
[runtime:2]
[6 hours:12]
[6 minutes:12]
[scheduleMode:2]
[scheduleDay:2]
[intervalYear:2]
[intervalMonth:2]
[intervalDay:2]
[enable:1]
[zone rain sensor follow:1]
```

Селектор зоны:

```text
1 << (zoneId - 1)
```

Для зоны 8 это `80`. Это совпадает с натурным инцидентом HO-SC-8W: запись с первым байтом `08` попала в зону 4.

## Byte 19 DP38 — уточнённая семантика

APK не работает с ним как с одним битовым полем. Последние два HEX-символа строятся независимо:

- старшая тетрада (`char 38`) — `isEnable()` программы;
- младшая тетрада (`char 39`) — `isSeaAdjSwitch()`.

Несмотря на имя bean-поля `SeaAdjSwitch`, экран `activity_iic800_add_plan` связывает его с `Obey / Ignore Rain Sensor`. Глобальная сезонная коррекция передаётся отдельно через DP103 `SeaAdjValue`.

На наших известных DP38 блоках хвосты `11` и `10` согласуются с такой трактовкой. Старшая тетрада `program_enabled` уже подтверждалась отдельными guarded write/read-back опытами на HO-SC-8W. Младшая тетрада `rain_sensor_follow` всё ещё требует отдельного физического переключения с полным 8/8 read-back.

## Reset программы зоны

APK `Iic800AddPlanPresenter.reset()` отправляет один DP38-блок с one-hot селектором зоны, нулевой длительностью, пустыми слотами `FF`, weekly mask `7F` и хвостом `01`. Этот пакет не переносится в HO-SC-8W как готовая команда: в нём присутствуют дата и флаги, которые могут зависеть от версии/состояния. Для нашего устройства безопаснее строить reset из свежего текущего блока и менять только подтверждённые поля.

## Прочие команды из APK

- DP102: `changeRainSensor()` читает текущий глобальный Rain Sensor state и отправляет его логическое отрицание; на HO-SC-8W write-семантика ещё не канонизирована.
- DP103: `changeSeaAdjValue(int)` отправляет целое значение сезонной коррекции; на HO-SC-8W запись уже подтверждена.
- DP105: `resetDevice()` отправляет `true`; опасная команда полного reset, для исследовательских тестов не использовать.
- DP109: `clearAlarm()`/сброс звукового time alarm отправляет `true`; без активной тревоги натурный эффект трудно доказать.
- DP111: APK IIC-800 имеет отдельную команду main valve. В подтверждённой карте HO-SC-8W DP111 отсутствует, поэтому перенос запрещён до обнаружения этого DP на нашем устройстве.

## Что можно улучшить в NikaS после физического теста

1. `skip_current_manual`: заменить пересборку из сохранённого локального плана на штатную DP45-модификацию с фактическими `remaining` + `watered` значениями.
2. Убрать зависимость `skip_current_manual` от `_manual_queue_plan`; после успешного T2 достаточно свежих DP45 + DP107.
3. `stop_manual`: проверить `01 00` all-zero как нативный Stop All и только после read-back решить, какой вариант оставить каноническим; уже подтверждённый `01 01` zero reset сохраняется как безопасный production-путь до этого теста.
4. DP38 decoder/UI: показывать отдельно `program_enabled` и `obey_rain_sensor`, не называть младшую тетраду сезонной коррекцией.
5. DP38 production writer: не считать `rain_sensor_follow` физически подтверждённым до T3, даже при точном APK-совпадении.
6. После натурного подтверждения `00 00` DP45 добавить явный native refresh перед live-модификациями, не смешивая его со Stop All.

## Следующие безопасные тесты HO-SC-8W

### T0 — DP45 native refresh

Во время короткого ручного полива снять обычный свежий DP45/DP107, затем отправить один 34-байтовый zero-query:

```text
00 00 + 32 × 00
```

Подтвердить, что:

- активная зона по DP107 не меняется;
- полив не останавливается и не перезапускается;
- приходит DP45 с `manualMode`, `remain` и `watered`;
- значения совместимы с состоянием непосредственно до запроса.

Если T0 не подтверждён, `00 00` не использовать в production.

### T1 — DP45 Stop All

Во время короткого ручного полива одной тестовой зоны снять полный DP45/DP107 до команды, отправить один штатный `01 00` + нули и подтвердить:

- DP107 → 0;
- DP45 banks → 0 или штатное idle-состояние;
- DP101 не переключается неожиданно;
- следующая автоматическая программа не повреждена.

### T2 — остановка текущей зоны с сохранением очереди

Запустить две короткие зоны. После начала первой зоны получить свежие DP45 + DP107. Сформировать кадр `01 <manualMode>` из фактических live-банков, обнулив оба 16-bit значения только текущей зоны. Проверить:

- первая зона выключилась;
- вторая зона стала активной без полного Stop All;
- её `remaining` не сбросился на исходно заданное значение против факта live-состояния;
- после перезапуска HA тот же алгоритм не нуждается в локально сохранённом плане.

### T3 — rain nibble DP38 на свободной зоне

Использовать только физически свободную зону и полный 8/8 baseline. Изменить исключительно младшую тетраду byte19 `1 ↔ 0` с правильным one-hot selector, затем получить полный 8/8 read-back и доказать неизменность остальных 7 зон и остальных байтов целевой зоны.

До T0–T3 production-управление новыми write-семантиками не расширять.
