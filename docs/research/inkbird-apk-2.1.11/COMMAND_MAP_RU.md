# HO-SC-8W / IIC-800 — карта команд из APK, Tuya Data Model и натурных испытаний

Исследуемое приложение: INKBIRD `com.inkbird.inkbirdapp` 2.1.11 (`versionCode 190`).  
Контроллер: INKBIRD / HiOazo HO-SC-8W, Tuya product ID `h71ip90tp4mfd6mx`, category `ggq`, protocol 3.3.

> Этот документ разделяет четыре уровня достоверности: **натурно подтверждено**, **подтверждено заводской Tuya Data Model**, **наблюдалось только как телеметрия**, **пока гипотеза**.

## 1. Подтверждённая карта DP

| DP | Tuya code | Тип/роль | Состояние исследования |
|---:|---|---|---|
| 38 | `normal_time` | строковый 20-байтовый блок программы одной зоны, передаваемый как 40 ASCII-HEX символов | чтение подтверждено; one-hot селектор записи подтверждён моделью и инцидентом; производственные записи пока заблокированы |
| 44 | `irrigation_mode` | режим исполнения зон | значение `order` используется для последовательной ручной очереди |
| 45 | `irrigation_time_all` | RAW 34 байта: ручной запуск/пересборка/общий стоп и текущие времена | натурно подтверждено |
| 101 | `operation_mode` | режим контроллера: Auto / Manual / OFF | не является командой открытия/закрытия клапанов |
| 102 | `RainSen_TotalONOFF` | состояние/настройка датчика дождя | карта подтверждена; запись отдельно не проверялась |
| 103 | `SeaAdjValue` | сезонная коррекция, число | запись натурно подтверждена; диапазон интерфейса −90…100, шаг 10 |
| 104 | `Merge_History` | объединённая история | телеметрия |
| 105 | `ResetDevice` | сброс устройства | опасная команда, не использовать без отдельного тест-плана |
| 106 | `timeerror_alarm` | ошибка времени | телеметрия |
| 107 | `zonerun_state` | битовая маска реально активных зон | авторитетный источник текущей активности |
| 108 | `pendingzone_state` | битовая маска ожидающих зон | на нашем экземпляре постоянно 0, даже когда внутренняя очередь работает |
| 109 | `cancel_timealarm_voice` | отключение звука тревоги | карта подтверждена; запись отдельно не проверялась |

## 2. DP45 — ручной полив

### Формат

Ровно 34 байта:

```text
байт 0      command
байт 1      target
байты 2–17  восемь времён зон, unsigned 16-bit big-endian
байты 18–33 второй банк времён, unsigned 16-bit big-endian
```

Для команды запуска используются:

```text
command = 0x01
target  = 0x01
первый банк = длительности выбранных зон в минутах
второй банк = 16 нулевых байтов
```

Пример: зона 1 — 10 минут, зона 3 — 20 минут:

```text
01 01 |
00 0A | 00 00 | 00 14 | 00 00 | 00 00 | 00 00 | 00 00 | 00 00 |
00 00 | 00 00 | 00 00 | 00 00 | 00 00 | 00 00 | 00 00 | 00 00
```

Общий стоп — тот же пакет `01 01`, но все 32 байта времён равны нулю.

### Семантика отчёта

- первый банк в отчётах наблюдается как оставшееся время;
- второй банк — как прошедшее время;
- факт открытого клапана подтверждается только DP107;
- DP45 без соответствующего бита DP107 не должен рисовать активный полив.

### Важное ограничение

DP101 нельзя использовать вместо DP45. Переключение DP101 меняет режим контроллера, но натурные испытания показали, что оно не является надёжной командой закрытия активного клапана.

## 3. DP38 — программа автоматического полива

### Формат одного блока

Ровно 20 байт:

| Байты | Значение |
|---|---|
| 0 | идентификатор/селектор зоны |
| 1 | длительность полива, минуты |
| 2–7 | часы шести возможных стартов |
| 8–13 | минуты шести возможных стартов |
| 14 | режим календаря: `0` weekly, `1` odd, `2` even, `3` interval |
| 15 | недельная маска либо интервал в днях |
| 16 | год как смещение от 2000 |
| 17 | месяц |
| 18 | день |
| 19 | флаги; бит 0 связан с учётом датчика дождя; остальные биты надо сохранять без изменений |

Неиспользуемый старт кодируется парой `FF / FF` в соответствующих банках часов и минут.

### Критическое различие чтения и записи

Контроллер **читает/отчитывает** обычный номер зоны:

```text
зона:       1  2  3  4  5  6  7  8
отчёт byte0 01 02 03 04 05 06 07 08
```

Команда **записи** выбирает зону one-hot маской:

```text
зона:        1  2  3  4  5  6  7  8
запись byte0 01 02 04 08 10 20 40 80
```

Именно поэтому прежний тест записи зоны 8 с первым байтом `08` затронул зону 4: в команде `08` означает четвёртый бит, а не номер восьмой зоны.

### Подтверждённый лабораторный пример зоны 8

Исходный отчёт зоны 8:

```text
0800FFFFFFFFFFFFFFFFFFFFFFFF03011A090411
```

Команда записи, меняющая только день `04 → 05`:

```text
8000FFFFFFFFFFFFFFFFFFFFFFFF03011A090511
```

Ожидаемый последующий отчёт:

```text
0800FFFFFFFFFFFFFFFFFFFFFFFF03011A090511
```

То есть только команда имеет первый байт `80`; в read-back контроллер снова возвращает `08`.

### Транспорт

DP38 объявлен строковым DP с ограничением 255 символов. Один блок отправляется как 40 символов uppercase ASCII-HEX. Полный кадр из восьми блоков занял бы 320 символов, превышает объявленный предел и не соответствует наблюдаемому контракту «одна зона — одна операция».

## 4. Безопасный алгоритм будущей записи DP38

1. Требовать локальное соединение, отсутствие активной и ожидающей зоны и свежую телеметрию.
2. До записи получить полный снимок зон 1–8 непосредственно от контроллера.
3. Взять фактический 20-байтовый блок нужной зоны и клонировать его целиком.
4. Заменить в байте 0 номер зоны на one-hot маску `1 << (zone - 1)`.
5. Изменить только запрошенное поле; неизвестные биты и байт 19 сохранить.
6. Отправить один раз один 20-байтовый блок как 40 uppercase HEX символов.
7. Не делать автоматический повтор и не пытаться откатить неподтверждённой командой.
8. Получить новый полный снимок зон 1–8.
9. Для изменённой зоны сравнивать байты 1–19 с целью, допуская возврат обычного номера зоны в байте 0.
10. Обязательно доказать, что остальные семь блоков не изменились.

До завершения отдельного контролируемого теста на физически свободной зоне общие и производственные редакторы DP38 должны оставаться заблокированными.

## 5. DP103 — сезонная коррекция

Это отдельный числовой DP, а не часть DP38. Натурно подтверждена запись значения и применение контроллером к автоматическому циклу.

Контракт интерфейса:

- значения −90, −80, …, 90, 100;
- изменение сначала формирует черновик;
- запись выполняется только кнопкой «Применить»;
- перед отправкой требуется подтверждение действия;
- после отправки требуется read-back DP103.

## 6. Что дал статический APK

INKBIRD 2.1.11 использует общий Tuya/Thing runtime. Статический APK содержит транспорт и загрузочную инфраструктуру, но окончательный вывод о месте product-specific кодировщика надо делать только по совпадениям точечного DEX/asset прохода.

Если точные строки `normal_time`, `irrigation_time_all`, `SeaAdjValue` и product ID отсутствуют в методах базового APK, наиболее вероятная архитектура — загружаемая из Tuya Cloud панель/mini-app. Тогда следующим источником должен быть не очередной полный JADX-разбор оболочки, а кэш или сетевой пакет самой панели после открытия страницы IIC-800.

## 7. Практический итог

- DP45 в текущей интеграции построен правильно.
- DP103 построен правильно.
- DP107 правильно выбран единственным авторитетным признаком активного полива.
- DP108 нельзя использовать как единственный источник очереди на нашем экземпляре.
- DP38 теперь имеет объяснённый read/write selector; `80` — запись зоны 8.
- Главный оставшийся вопрос — не базовая разметка DP38, а безопасная проверка реальной записи всех типов полей: время, длительность, цикл, дата и rain flag.
