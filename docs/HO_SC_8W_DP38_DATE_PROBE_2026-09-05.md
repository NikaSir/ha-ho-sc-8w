# HO-SC-8W — DP38: подтверждённый интервал и следующий тест даты

Дополнение к `HO_SC_8W_CONTROLLER_KB_RU.md` и `HO_SC_8W_CONTROLLER_KB_CONFIRMED_2026-09-04.md`.
Дата: 2026-09-05. Устройство: физический NikaS INKBIRD / HiOazo HO-SC-8W.

## Натурные результаты, полученные от оператора

Скриншоты UI 0.6.78: `IMG_1988.png`, `IMG_1989.png`, `IMG_1990.png`.
Сравнение двух полных снимков 8/8 показывает единственное изменение Z7:

```text
before = 0711060C17FFFFFF1E2D3BFFFFFF03011A090310
after  = 0711060C17FFFFFF1E2D3BFFFFFF03021A090310
byte 15: 01 -> 02
```

Зоны 1–6 и 8 не изменились; интерфейс сообщил успешный полный read-back.
Во вкладке «Программа» показаны период 2 дня, 17 мин, старты 06:30 / 12:45 / 23:59,
дата 03.09.2026 и выключенный учёт дождя. Время снимка на скриншоте: 05.09.2026 08:19.

Это подтверждает изолированную запись и сохранение значения `02` в byte 15 при
неизменном byte 14 = `03`. Пропуск контроллером полива в промежуточный календарный
день в данном эксперименте отдельно не наблюдался. Расчёт ближайшего запуска
в нашей панели сам по себе не доказывает поведение планировщика прошивки.

Предыдущими представленными оператором тестами подтверждены слоты 1–3:
часы в byte 2/3/4, минуты в byte 8/9/10; значение третьего слота 23:59
сохранилось как `17` / `3B`. Схема слотов 4–6 соответствует референсу APK и декодеру,
но отдельной физической записью каждого из этих слотов в данной серии не проверялась.

## Следующий эксперимент: день опорной даты 03 -> 04

Версия подготовки: integration `1.0.0-b006.2`, UI `0.6.79`.
Статус: подготовлен для натурного тестирования, физическая запись даты ещё не подтверждена.

```text
source READ   = 0711060C17FFFFFF1E2D3BFFFFFF03021A090310
planned WRITE = 4011060C17FFFFFF1E2D3BFFFFFF03021A090410
expected READ = 0711060C17FFFFFF1E2D3BFFFFFF03021A090410

byte 0:  07 -> 40  READ identifier -> one-hot WRITE selector
byte 18: 03 -> 04  день опорной даты
```

Нумерация байтов — с нуля; информационное изменение только одно: byte 18.
17 мин, все шесть временных слотов, режим `03`, период `02`, год `1A`, месяц `09`
и флаги `10` должны сохраниться. Глобальная сезонная коррекция не изменяется.

## Ограничения и приёмка

Подготовка получает отдельный свежий снимок 1–8. Исходный 20-байтовый Z7 должен
точно совпасть с `source READ` выше. Проверяются не только позиции diff, но и
полные значения планируемого WRITE и expected READ. Любое отличие блокирует план.
Разрешена только фиксированная цель `anchor_date = 2026-09-04`, не произвольная дата.

После dry-run оператор проверяет diff; запись выполняется отдельной кнопкой с
подтверждением. Используется существующий writer: локальный транспорт, отсутствие
активного полива/очереди, Auto/ON, новый preflight 1–8, одна запись Z7, полный read-back
1–8. Автоматического запуска записи, повтора или отката нет. При ошибке запись не
повторять до анализа фактического состояния. Остальные зоны не редактируются.

Приёмка записи: exact expected READ у Z7 и побайтная неизменность зон 1–6 и 8.
После этого отдельно проверяется календарный эффект изменения опорной даты.
По модели интервала с шагом 2 дня даты 03/05/07… заменяются на 04/06/08… сентября.
Это ожидаемый эффект, не результат уже выполненного натурного наблюдения.

Установка интеграции и открытие вкладок сами по себе дату в контроллере не меняют.
Программные тесты guard и generic writer используют имитацию I/O и не являются
физическим подтверждением нового поля.
