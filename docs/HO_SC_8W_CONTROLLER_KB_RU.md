# HO-SC-8W — каноническая база знаний по управлению контроллером

Дата ревизии: 2026-09-04
Статус: каноническая исследовательская БЗ для проекта NikaS Home Assistant.

## 1. Область действия

Эта БЗ относится к физическому контроллеру INKBIRD / HiOazo HO-SC-8W, используемому в проекте NikaS Home Assistant.

INKBIRD IIC-800 из APK INKBIRD 2.1.11 используется только как протокольный референс. Аппаратная идентичность IIC-800 и HO-SC-8W не считается доказанной. Любое поведение из APK принимается для HO-SC-8W только если оно совпадает с нашей DP-картой, длиной/структурой кадров и/или подтверждено натурным read-back.

Внешний профиль `make-all/tuya-local sh07_sprinkler_controller` не является профилем HO-SC-8W и используется только как сравнительный источник методики.

## 2. Идентификация устройства

- Модель проекта: HO-SC-8W.
- Число зон контроллера: 8.
- В проекте физически используются зоны 1–6; зоны 7–8 применяются как свободные лабораторные зоны.
- Tuya category: `ggq`.
- Product ID: `h71ip90tp4mfd6mx`.
- Локальный протокол: Tuya 3.3.
- Предпочтительный рабочий транспорт: Local.

## 4. DP38 — программа автоматического полива

### 4.1. Размер и транспорт

Одна зона = один блок 20 байт.

DP38 является Tuya String DP и записывается как 40 uppercase ASCII-HEX символов.

Нельзя:

- отправлять полный 160-байтовый кадр всех зон;
- кодировать DP38 как Base64;
- использовать номер зоны в byte0 при записи.

### 4.2. Формат 20-байтового блока

| Byte | Поле |
|---:|---|
| 0 | READ: номер зоны 1..8; WRITE: one-hot selector |
| 1 | длительность полива, минуты |
| 2..7 | часы стартов 1..6 |
| 8..13 | минуты стартов 1..6 |
| 14 | `scheduleMode` |
| 15 | `scheduleDay` / параметр календарного режима |
| 16 | YY |
| 17 | MM |
| 18 | DD |
| 19 high nibble | Enable программы |
| 19 low nibble | Obey/Ignore Rain Sensor для программы |

Неиспользуемый слот времени хранится как `FF/FF`.

### 4.3. Критическое различие READ и WRITE selector

При чтении контроллер возвращает обычный номер зоны:

```text
zone 1 2 3 4 5 6 7 8
READ 01 02 03 04 05 06 07 08
```

При записи требуется one-hot selector:

```text
zone 1 2 3 4 5 6 7 8
WRITE 01 02 04 08 10 20 40 80
```

Формула:

```text
1 << (zone - 1)
```

Критический исторический факт: запись зоны 8 с byte0=`08` выбрала зону 4. Корректный selector зоны 8 — `80`.

### 4.4. Calendar mode

Подтверждено APK UI bytecode:

```text
00 = Weekly
01 = Odd days
02 = Even days
03 = Interval
```

### 4.5. Weekly mask

Порядок битов подтвержден `WeekAdapter` APK:

```text
01 = Sunday
02 = Monday
04 = Tuesday
08 = Wednesday
10 = Thursday
20 = Friday
40 = Saturday
7F = все дни
```

Примеры:

```text
Mon-Fri    = 3E
Sat+Sun    = 41
Mon+Wed+Fri = 2A
```

### 4.6. Interval

Для `scheduleMode=03` byte15 хранит число дней интервала.

Bytes 16..18 = дата-якорь `YY MM DD`.

Год отображается как `2000 + YY`.

### 4.7. Odd / Even

`01=Odd`, `02=Even` подтверждены вызовами UI APK.

Семантика служебного byte15 для Odd/Even на HO-SC-8W пока не канонизирована как отдельное writable-поле. При редактировании других параметров его надо сохранять из свежего read-блока.

### 4.8. Byte19 — флаги программы

APK строит последний байт двумя независимыми HEX-тетрадами:

```text
high nibble = program Enable
low nibble  = Obey/Ignore Rain Sensor
```

Структурно:

```text
11 = программа ON  + учитывать Rain Sensor
10 = программа ON  + игнорировать Rain Sensor
01 = программа OFF + учитывать Rain Sensor
00 = программа OFF + игнорировать Rain Sensor
```

`11/10` согласуются с нашими реальными DP38 блоками.

`01/00` подтверждены энкодером APK, но ещё не доказаны физическим read-back HO-SC-8W.

Важно: `enabled` нельзя определять как `duration > 0`.

Глобальная сезонная коррекция не находится в byte19. Она хранится отдельно в DP103.

## 5. Безопасная архитектура записи DP38

Канонический алгоритм — transactional read-modify-write.

### 5.1. Prepare

1. Контроллер должен быть доступен локально.
2. Активного/очередного полива быть не должно.
3. Получить свежий полный snapshot всех 8 зон.
4. Взять свежий 20-байтовый READ block целевой зоны.
5. Скопировать его byte-for-byte.
6. Изменить только запрошенное поле.
7. Преобразовать byte0 `zone -> one-hot` только в write-копии.
8. Построить expected read-back, вернув byte0 к обычному номеру зоны.
9. Показать diff до физической записи.

### 5.2. Execute

Перед отправкой обязательно повторно снять полный snapshot 8/8.

Если хоть один блок изменился после prepare — транзакцию отменить.

После этого:

1. отправить ровно один 20-байтовый DP38 block;
2. не retry;
3. не выполнять автоматический rollback;
4. повторно считать все 8 зон;
5. целевая зона должна совпасть с expected read-back;
6. остальные 7 зон должны остаться byte-for-byte неизменными.

Любой timeout после dispatch считать неоднозначным: команда могла уже попасть в контроллер.

### 5.3. Запрещено

- blind write без свежего read;
- пересборка неизвестных полей с нуля;
- автоматическая нормализация byte19;
- retry DP38 после timeout;
- auto rollback DP38;
- изменение нескольких production-зон одной операцией;
- перенос reset-пакета IIC-800 как готовой команды HO-SC-8W.

## 6. Текущий лабораторный DP38 путь

Для безопасной верификации разработан отдельный Zone-7 Lab.

Свободная зона 7 используется как первая тестовая зона.

Первый фиксированный сценарий:

```text
READ zone 7: byte0 = 07
WRITE zone 7: byte0 = 40
duration: byte1 -> 0x11 = 17 min
```

Сервисы research-ветки:

```text
nikas_ho_sc_8w.prepare_zone7_duration17
nikas_ho_sc_8w.execute_zone7_duration17
```

Execute требует подтверждение:

```text
WRITE_ZONE7_DURATION_17_ONCE
```

До физического подтверждения этого сценария production DP38 write не разблокировать.

## 7. DP45 — ручной полив

### 7.1. Формат

DP45 = 34 байта:

```text
byte 0     command type
byte 1     target/manual mode
bytes 2..17   8 x uint16 BE — первый банк
bytes 18..33  8 x uint16 BE — второй банк
```

Каждая зона занимает uint16 big-endian.

### 7.2. Семантика банков

В start-команде первый банк содержит заданные длительности, второй банк = 0.

В live report наблюдается:

- первый банк — remaining;
- второй банк — elapsed/watered.

Для определения фактической активности нельзя полагаться только на ненулевой DP45. Авторитетный факт активности — DP107.

### 7.3. Подтвержденный рабочий manual start HO-SC-8W

Для последовательной очереди:

```text
command = 01
target  = 01
```

Первый банк = длительности выбранных зон, остальные 0.

Второй банк = 0.

Если требуется последовательный режим, DP44 устанавливается в `order`.

Ключевой факт: DP101 не является командой запуска клапана.

Нельзя перед manual start сначала полагаться на DP101=Manual как на исполнительную команду.

### 7.4. DP107 / DP108

DP107 — реальная маска работающих зон и главный источник подтверждения старта/перехода/стопа.

DP108 на нашем контроллере может оставаться `0` даже при реально работающей внутренней очереди. Поэтому очередь нельзя восстанавливать только из DP108.

Текущая интеграция хранит отправленный manual plan локально в runtime для безопасного skip.

### 7.5. Skip current — текущий рабочий алгоритм

Текущий NikaS путь:

1. DP107 должен показывать ровно одну активную production-зону.
2. Текущая зона должна существовать в `_manual_queue_plan` текущего runtime.
3. Из плана удаляется текущая и уже пройденные зоны.
4. Через DP45 `01 01` повторно отправляется только остаток.
5. DP107 должен подтвердить следующую зону либо 0, если очередь закончилась.

Если интеграция перезапускалась и локальный план утрачен, безопасный skip запрещается — нужен Stop All.

APK IIC-800 показывает более общий вариант модификации live DP45 с сохранением фактических remaining/watered; на HO-SC-8W он ещё не канонизирован физическим тестом.

### 7.6. Stop All — физически рабочий путь HO-SC-8W

Текущая интеграция использует:

```text
01 01 + все 32 bytes времени = 0
```

Физически подтверждено, что DP107 уходит в 0.

DP101=Auto/OFF не использовать как замену Stop All: поле режима может измениться без фактического закрытия активного клапана.

### 7.7. Штатная матрица IIC-800 из APK

Референс APK:

```text
01 01 = старт selected zones sequential
02 01 = modify running sequential
01 00 = start all zones simultaneously / all-zero = native Stop All
02 00 = modify running simultaneous
```

`01 00 + zero banks` ещё требует A/B физического теста на HO-SC-8W, поэтому production-код автоматически на него не переводить.

## 8. DP101 — Operation Mode

DP101 хранит режим Auto / Manual / OFF.

Каноническое правило:

> DP101 — состояние/режим контроллера, но не надёжная команда открытия или закрытия клапана.

Нельзя использовать DP101 как замену DP45 для ручного запуска или Stop All.

## 9. DP103 — сезонная коррекция

DP103 `SeaAdjValue` — отдельное числовое значение.

Подтвержденный диапазон проекта:

```text
-90 .. +100 %
step = 10 %
```

Канонический UI/workflow:

1. пользователь меняет draft;
2. нажимает «Применить»;
3. подтверждает действие;
4. записывается DP103;
5. обязательно проверяется read-back того же значения.

На главной странице сезонная коррекция только отображается; изменение выполняется на странице программы/настроек.

## 10. DP44 — irrigation mode

Используемое подтвержденное значение:

```text
order
```

Оно означает последовательное выполнение выбранных ручных зон.

Другие режимы не считать канонически поддержанными HO-SC-8W без отдельного теста.

## 11. DP102 / DP109 / DP105

### DP102

Rain sensor enable/status. Чтение используется. Запись не канонизирована.

### DP109

Cancel alarm voice. Назначение известно, запись на нашем устройстве не подтверждена.

### DP105

ResetDevice. Потенциально разрушительная команда. В нормальном управлении интеграции не должна использоваться.

## 12. Транспортные правила

### DP38

- Tuya String DP.
- 20 bytes -> 40 uppercase ASCII HEX.
- one-hot selector в byte0 на write.

### DP45

- RAW DP.
- локальный транспорт использует Base64-представление raw payload для Tuya API.
- cloud path использует соответствующий raw/hex payload согласно transport wrapper.

Нельзя переносить кодирование DP45 на DP38 и наоборот.

## 13. Источники истины по состоянию

Порядок доверия:

1. свежий локальный read-back контроллера;
2. DP107 для факта работающей зоны;
3. свежий полный DP38 snapshot для программ;
4. DP45 live banks для remaining/elapsed;
5. DP101 для режима;
6. DP108 только как дополнительная телеметрия, не как единственный источник очереди;
7. локальный runtime plan только как вспомогательная память для команд, которые сама интеграция отправила в текущем runtime.

## 14. Уровни доказанности

### A — физически подтверждено HO-SC-8W

- DP38 read block = 20 bytes.
- DP38 write zone selector — one-hot; зона 8 = `80`.
- запись с `08` выбрала зону 4.
- DP45 `01 01` запускает manual queue.
- DP45 `01 01` с нулевыми временами останавливает manual watering.
- DP107 подтверждает реально активную зону.
- DP108 ненадёжен для очереди на нашем экземпляре.
- DP101 сам по себе не является надёжной командой клапана.
- DP103 seasonal adjustment writable/read-back подтвержден.

### B — подтверждено APK IIC-800 и совпадает со структурой HO-SC-8W

- DP38 byte layout.
- one-hot формула `1 << (zone-1)`.
- 6 start slots.
- calendar modes 0/1/2/3.
- weekday bit map Sun=01 ... Sat=40.
- byte19 high nibble = Enable.
- byte19 low nibble = Obey/Ignore Rain Sensor.
- DP45 native matrix `01/02 x 00/01`.
- `01 00 + zeros` как IIC-800 Stop All.

### C — ещё требует физического теста HO-SC-8W

- byte19 `01/00` на выключенной программе.
- изменение Rain Sensor nibble DP38.
- полноценное изменение Enable DP38.
- Odd/Even служебный byte15 write behavior.
- Interval edit целиком через наш writer.
- IIC-800 `01 00` Stop All на HO-SC-8W.
- native DP45 modify `02 01`.
- DP102 write.
- DP109 write.

## 15. Следующая программа тестов

1. Zone 7 duration 0 -> 17 через transactional writer.
2. Проверить full 8/8 read-back и отсутствие collateral changes.
3. Zone 7 Enable OFF/ON.
4. Zone 7 Rain Sensor follow 1/0.
5. Zone 7 Weekly mask.
6. Zone 7 start slot.
7. Zone 7 Interval.
8. Только после успешной серии — проектировать production editor зон 1–6.
9. Отдельно провести DP45 A/B Stop All `01 01 zeros` vs APK `01 00 zeros`.
10. Только после подтверждения решить, какой Stop All сделать каноническим.

## 16. Канонические правила для будущего кода

1. Никаких raw-DP generic controls в UI.
2. Все записи — через специализированные validated services/actions.
3. Любая запись требует подтверждения пользователя.
4. DP38 — transactional RMW с full snapshot до и после.
5. После transport dispatch не retry.
6. После mismatch не auto rollback.
7. DP45 start/skip/stop подтверждать по DP107.
8. DP101 не использовать как клапанную команду.
9. DP108 не считать истиной очереди.
10. Seasonal adjustment — DP103, шаг 10%, кнопка «Применить» + подтверждение + read-back.
11. Production zones 1–6 не использовать для лабораторных экспериментов.
12. IIC-800 — reference, не идентичность.

## 18. Короткая памятка

Если нужно запомнить только пять вещей:

1. DP38 write byte0 — **маска**, не номер зоны.
2. DP45 управляет ручным поливом; DP101 — не клапан.
3. DP107 — факт работающей зоны; DP108 ненадёжен.
4. DP38 писать только через fresh read -> patch -> one write -> full read-back.
5. IIC-800 помогает расшифровывать протокол, но не заменяет физическую проверку HO-SC-8W.
